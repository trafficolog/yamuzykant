# 1.2.3. Справочники: доработки после ревью

## Цель
Повторный сид не затирает решения сотрудников, а публичные запросы к справочникам дешёвые (неблокирующие замечания ревью PR #85).

## Что сделать
- `CategorySeeder`, `InstrumentModelSeeder`: `is_visible` и `status` задаются только при создании записи (`firstOrCreate` + обновление нейтральных полей), правки из консоли сохраняются
- Уникальность корневых категорий: частичный уникальный индекс для `parent_id IS NULL` (pgsql) или эквивалент
- `InstrumentModel::scopePublic` — без отдельного запроса `visibleIds()` при построении (join/подзапрос), чтобы подсказка 1.2.2 делала один запрос
- Shared prop `categories` — кэш с инвалидацией при изменении категорий
- `CategoryResource`: явная ошибка или `whenLoaded` вместо молчаливого `[]`
- Тест сверки с меню `Шапка.dc.html`: снимок меню в `tests/fixtures` или регулярка, устойчивая к отступам и кавычкам
- `.gitignore`: файл sqlite `/ymuzykant`, который создаётся при `.env` из примера
- `cities.slug` (1.1.4): backfill в миграции или шаг деплоя для окружений с уже заполненными городами — иначе город по умолчанию не найдётся
- Тест: вошедший с несуществующим `city_id` → 422, `users.city_id` не меняется
- Подсказка модели (ревью PR #92): наблюдатель категорий реагирует и на `parent_id`, и на удаление; тест на запас ×3 при выборке из индекса; уникальность `(brand, name)` без учёта регистра (индекс по `lower()`); текст 429 суточного лимита предложений — в `lang/ru`; в описании отразить лимит POST предложений 30/мин
- Тестовый каркас (ревью PR #97): `FeatureFlagsTest` — `toBe(1)` вместо `≤ 1`; чистые Unit-тесты без БД — группа `no-database`; сверка FLAG_NAMES с enum устойчива к формату записи `case`
- Данные: годы Gibson Les Paul Studio (с 1983), Strymon Timeline (2012)
