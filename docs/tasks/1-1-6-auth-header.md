# 1.1.6. Шапка вошедшего: данные пользователя, меню кабинета, выход

## Цель
После входа шапка и нижняя панель показывают вошедшего пользователя, а не «Войти» (вопрос исполнителя PR #113).

## Что сделать
- Shared prop `auth.user` в HandleInertiaRequests: только id, имя, город, признак сотрудника; без почты, yandex_id и других ПДн (BR-04)
- Шапка: вместо «Войти» — меню кабинета (разделы «Покупаю» / «Продаю», «Сообщения», «Избранное», «Выйти») по макету и DEVIATIONS (G1-preliminary: account nav); нижняя панель — «Кабинет» ведёт в кабинет
- Выход: POST `/auth/logout` (маршрут с 1.1.1) с CSRF, сброс сессии и regenerate token; возврат на главную
- Кнопки «Написать», «В избранное», «Продать» у гостя открывают окно входа с колбэком (`onAuthenticated` из 1.1.2), у вошедшего — действие
- Тексты — в `lang/ru.ts`
- Кнопка «Войти» до гидратации: прогрессивное улучшение (ссылка на страницу входа без JS) или отложенный клик; в e2e — явный признак гидратации вместо `networkidle` (ревью PR #113)
- e2e `forgetYandexTestUser`: отказ при `APP_ENV` не `e2e`/`testing`; тесты `safeReturnPath` на путь с табуляцией и с переводом строки после первого слэша (ревью PR #113)

## Критерии приёмки
- [ ] После входа без перезагрузки страницы шапка показывает меню кабинета (e2e)
- [ ] В HTML и JSON-ответах Inertia нет почты и yandex_id пользователя (тест)
- [ ] Выход завершает сессию; повторный POST со старым CSRF — 419 (тест)
- [ ] Definition of Done — AGENTS.md §3

## Тесты (пишутся первыми)
- Pest: shared prop без ПДн, logout; Vitest: шапка гость/вошедший; Playwright: вход → меню → выход
