# 0.1.13. Content-Security-Policy с nonce для Inertia и SSR

## Цель
Страницы отдают CSP без `unsafe-inline` в скриптах (ARCHITECTURE §7; ревью PR #96, п. 7).

## Что сделать
- Middleware: nonce на запрос, заголовок `Content-Security-Policy` (`default-src 'self'`; `script-src 'self' 'nonce-…'`; `style-src` — по факту ДС; `img-src` — свой origin и хранилище фото; `connect-src` — свой origin и Reverb `wss:`; `font-src 'self'`; `frame-ancestors 'none'`; `base-uri 'self'`; `form-action 'self'`)
- Nonce в Vite-тегах (`Vite::useCspNonce()`), в данных Inertia и SSR-разметке
- Сначала `Content-Security-Policy-Report-Only` на stage, затем принудительный режим
- Заголовки безопасности в Nginx (deploy/nginx) не дублируют CSP приложения

## Критерии приёмки
- [ ] На `/`, `/_ds` (local/stage) и страницах G1 нет нарушений CSP в консоли (Playwright собирает `securitypolicyviolation`)
- [ ] Встроенный скрипт без nonce блокируется (тест)
- [ ] Definition of Done — AGENTS.md §3

## Тесты (пишутся первыми)
- Pest feature: заголовок и nonce; Playwright: нет нарушений, блокировка скрипта без nonce

## Не делать
- `unsafe-inline` / `unsafe-eval` в `script-src`
