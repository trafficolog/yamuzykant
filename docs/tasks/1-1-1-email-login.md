# 1.1.1. Вход по коду на почту: бэкенд

## Цель
Пользователь входит по одноразовому коду из письма; почта — идентификатор аккаунта (SPEC UC-A1).

## Что сделать
- Таблица users: email (unique, хранится в нижнем регистре), yandex_id (unique, nullable — заполняет 1.1.5), name, city_id, notification_prefs jsonb, consent_version, consented_at, last_login_at
- `POST /auth/email/code` (отправить), `POST /auth/email/verify` (проверить): код 6 цифр, TTL 10 мин (уточнить, в конфиге), хэш в Redis; новый код отменяет прежний
- Письмо `LoginCodeMail` — простой Markdown-шаблон (тема ДС — в 4.4.1), в очереди с высоким приоритетом
- Rate-limit: 5 кодов/час на адрес, 20/час на IP; 5 неверных попыток с одного IP на почту — блок 15 мин для пары почта+IP; общий потолок — 30 неверных в час на почту со всех IP, затем блок проверки для почты на 1 ч (решение OWNER 03.11.2026: чужая почта не даёт держать аккаунт заблокированным); счётчики атомарны
- Первый вход: аккаунт создаётся только вместе с согласием (версия документа) и именем; город — необязательно (подставляется из шапки). Пока согласия нет — состояние «нужна регистрация» в сессии, без записи в users
- Общий сервис `CompleteLogin` (создать или найти пользователя, согласие, сессия, возврат к действию) — его же использует 1.1.5
- Сессия Laravel, «выйти на всех устройствах»
- `LOGIN_CODE_FAKE` задаёт фиксированный код для тестов только в окружениях из закрытого списка `testing` и `e2e` (CI e2e работает с `APP_ENV=e2e`); в любом другом окружении переменная игнорируется
- Почтовый провайдер — уточнить у OWNER; local — Mailpit, CI — `array`

## Критерии приёмки
- [ ] Код не попадает в логи, ответы API и Sentry
- [ ] 6-й код за час → 429 с текстом «Слишком много попыток. Повторите через N мин»
- [ ] Неверный код 5 раз → блок 15 мин даже с верным кодом
- [ ] Ответ на запрос кода одинаковый для существующей и новой почты (нет перебора аккаунтов)
- [ ] Первый вход создаёт пользователя только с согласием и пишет версию документа
- [ ] `LOGIN_CODE_FAKE` не действует при APP_ENV `local`, `stage`, `production` (тест на каждое)
- [ ] Definition of Done — AGENTS.md §3

## Тесты (пишутся первыми)
- Pest unit: генерация и проверка кода, TTL, нормализация почты
- Pest feature: все ветки verify, rate-limit по адресу и IP, согласие, одинаковый ответ для новой и существующей почты
- Pest: код отсутствует в логах (Log::spy), письмо уходит в очередь (Mail::fake)

## Не делать
- Не делать вход по паролю и по телефону
- Не делать вход через Яндекс ID — это 1.1.5
