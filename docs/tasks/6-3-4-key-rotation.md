# 6.3.4. Ротация APP_KEY и перешифровка серийных номеров

## Цель
Смена ключа приложения не ломает чтение зашифрованных данных (серийный номер, задания очереди), а старые данные перешифровываются (ревью PR #100).

## Что сделать
- `APP_PREVIOUS_KEYS` в `.env.example` и ARCHITECTURE §9; процедура ротации в RUNBOOK
- Команда перешифровки `listings.serial_enc` (и других encrypted-полей) новым ключом, идемпотентная, пакетами, с отчётом
- Тест: данные, зашифрованные старым ключом, читаются при `APP_PREVIOUS_KEYS`; после команды — только новым

## Критерии приёмки
- [ ] Ротация на копии БД: маска серийного номера отдаётся до и после перешифровки, `DecryptException` нет
- [ ] Definition of Done — AGENTS.md §3

## Тесты (пишутся первыми)
- Pest feature: чтение старым ключом через previous keys; команда перешифровки

## Не делать
- Хранить старые ключи в репозитории
