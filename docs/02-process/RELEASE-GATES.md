# Релиз-гейты

Гейт — контрольная точка между фазами. Пока гейт не подписан, задачи следующего гейта не берутся в работу (`docs-ops next` их не выдаёт). Каждому гейту соответствуют веха GitHub, тег и документ `docs/operations/gates/G{n}.md`.

## Общие правила

1. **Состав.** Гейт включает все задачи с `gate: G{n}`. Перенести задачу в следующий гейт можно только с подписью OWNER и записью в документе гейта.
2. **Доказательства.** Каждый пункт чек-листа подтверждается ссылкой: run CI на коммите гейта, отчёт Playwright (артефакт), скриншот, запрос в БД stage.
3. **Аудит.** REV-`opus` проверяет чек-лист и все PR вехи (`ORCHESTRATOR.md §4.3`). Вердикт `fail` — гейт не проходит.
4. **Подпись.** OWNER отвечает «подтверждаю G{n}» в issue гейта. Без подписи тег не ставится.
5. **Тег и выпуск.** `git tag v{x}.{y}.0` на коммите `main`, на котором прошёл CI; push тега запускает `release.yml`, который создаёт GitHub Release с примечаниями без выкатки. Выкатка production (G3, `v1.*`) — отдельно, ручным запуском `release.yml` OWNER.
6. **Откат гейта.** Если после подписи найден блокирующий дефект (данные, безопасность, сценарий UC гейта), гейт переоткрывается, создаётся задача `fix` с `risk: high`.

**Блокирующий дефект** — падение UC гейта, потеря или утечка данных, обход прав, 5xx на ключевом пути, нарушение 152-ФЗ.

- [ ] Вход через настоящий Яндекс ID проверен на stage вручную (скриншот); письмо с кодом доходит через почтового провайдера.
- [ ] Визуальные тесты в пороге: `home`, `flea`, `flea-empty`, `lot`, `seller`, `sell-step*`, `sell-published`, `account-listings`, `account-favorites`, `messages`, `auth-*`; шапка на 390 px — по чек-листу SCREENS §3 (эталона нет, решение OWNER 03.11.2026).
- [ ] Переходы `ListingStateMachine` покрыты тестами на 100 %.
- [ ] Серийный номер не утекает: тест на props, индекс и логи.
- [ ] Фото: EXIF удаляется (тест на файле с GPS).
- [ ] Поиск: p95 ≤ 300 мс на сиде 100 тыс. объявлений (отчёт k6 или Pest benchmark).
- [ ] Флаг `premoderation` выключен: объявление видно в выдаче ≤ 60 с после публикации; объявление с контактами в тексте не публикуется (e2e).

- [ ] Коды входа не попадают в логи и Sentry (тест); rate-limit на коды и сообщения работает (тест).
- [ ] Отличия окна входа и кабинета от макетов в `DEVIATIONS.md` подтверждены OWNER.
