# Ревью PR

Ревьюер работает в новом контексте. Вход: карточка, diff, отчёты CI (тесты, покрытие, визуальные сравнения, axe). Результат: комментарии в PR и последняя строка итогового комментария — `REVIEW: approve` или `REVIEW: changes`. Оркестратор перед мержем проверяет её командой `node tools/docs-ops.mjs check --pr N`.

## Чек-лист

**Объём и спецификация**
- [ ] PR закрывает ровно одну карточку; изменений вне её объёма нет.
- [ ] Каждый критерий приёмки есть в таблице «критерий → тест», и тест действительно проверяет критерий.
- [ ] Коммит `test(...)` идёт раньше `feat(...)`, тесты в нём падали (видно по CI на этом коммите или по описанию).

**Код**
- [ ] Правила `AGENTS.md §4`: тонкие контроллеры, статусы через state machine, Policies, Resources без лишних полей.
- [ ] DRY, KISS, YAGNI (`AGENTS.md §4`): нет дублирования правил и логики при существующем источнике, нет лишних абстракций, нет кода «на будущее» вне карточки.
- [ ] Нет утечек ПДн: e-mail, `yandex_id`, коды входа и полный серийный номер не попадают в props, логи, индекс.
- [ ] Ошибки обработаны: пустые, граничные, конкурентные случаи (двойная отправка, гонка статусов).
- [ ] Миграции обратимы или откат описан; индексы под новые запросы есть.
- [ ] Новые зависимости обоснованы.

**Интерфейс** (если есть `prototype`)
- [ ] Только компоненты `@ds` и `resources/js/Components`; нет hex, rgb, своих шрифтов.
- [ ] Визуальное сравнение в пороге на 1440 и 390 px; отличия либо исправлены, либо внесены в `DEVIATIONS.md`.
- [ ] 8 состояний; клавиатура; axe чистый; тексты по `AGENTS.md §5`.
- [ ] Элементы вне MVP скрыты флагом, а не удалены из общих компонентов.

**Безопасность** (обязательно для `risk: high`)
- [ ] Rate-limit, авторизация каналов и маршрутов, проверка владельца ресурса.
- [ ] Входные данные валидируются на сервере, а не только на клиенте.

## Вердикт

- `approve` — все пункты выполнены или нерелевантны.
- `changes` — хотя бы один пункт не выполнен. Каждый комментарий начинается с номера пункта и предлагает конкретное исправление.
- Ревьюер не правит код сам и не одобряет при красном CI.
